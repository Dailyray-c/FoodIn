## v2.36.0  <sub>2026-09-22</sub>

- 人工「正常减少库存」改为统一二次确认：弹窗明确列出商品名称、当前库存、本次减少数量与减少后剩余库存，点「确认减少」才真正扣减；点「取消」则库存与流水完全不变、不产生任何记录。此前只有「最后一件」才弹确认，其余数量点一下就直接扣掉，误触无法挽回
- 确认按钮防重复提交：提交瞬间即置灰并显示加载状态，连点也只会扣减一次（扣减改到下一帧执行，避免同帧关闭弹窗造成重复入账）
- 修复「改完没反应 / 删不掉」：云同步 upsert 与 CSV 导入都可能让同一个 id 存在两条商品，此前改名、删除永远作用在第一条上。现在定位一律优先用对象引用；设置页可一键拆分重复 id（并把属于该商品的流水一并迁移），清理顺序改为「先拆 id 再清幽灵商品」
- 编辑弹窗打开时锚定商品对象引用，列表重排后保存不会再落到别的商品上
- 保质期单位与日期反算修复：默认单位由「月」改为「日」（原默认值会让单位按钮一进页面就停在「月」）；自动挑选最自然单位并保证正反算往返无损，正算不再多减 1 天
- 顶栏四张统计卡改为数据表驱动，第一张固定为「在库」（商品维度、件数口径）；「件」统一为 in / eat / waste 三类记录的数量合计，与列表口径一致
- 记录类型筛选支持多选，选中态背景色与类型标签配色适配

## v2.34.4–2.34.13  <sub>2026-09-19</sub>

- 新增（录入页 / 批量录入页也能云同步）：原来只有首页顶栏有云同步按钮，录完一批商品还得先退回首页才能确认数据有没有上云。现在普通录入页和批量录入页的顶栏也放了同一个按钮，行为完全一致——同步逻辑本身是全局的，这里只是让入口跟着「你正在产生数据」的地方走。
- 新增（自动同步现在看得见了）：数据改动后会有一个 15 秒的防抖自动同步，此前它是**完全静默**的——你根本不知道数据到底上没上云。现在顶栏那个云同步按钮兼作状态指示灯：同步中显示靛蓝色并转圈，成功变绿色并短暂显示「已同步到云端」（约 2.4 秒后淡出），失败变红色并常驻显示失败原因，直到下一次同步成功。文字是挂在按钮右侧的轻量气泡，不占布局、不打断任何操作。手动点「立即同步」仍然弹原来的提示条——那是你主动发起的，需要一个明确回执。
- 新增（需要跳转的引导弹窗现在有行动按钮）：像「文字识别已关闭」这类提示，原本只能告诉你「请先去设置里开启」然后让你自己找路。现在这类弹窗底部会有两枚按钮——左边「知道了」，右边直接写清去处（如「去设置开启」），点一下就把你送到该去的地方，不再需要自己翻菜单。
- 优化（说明弹窗统一为卡片样式）：原来有一批说明弹窗是各写各的遮罩和样式，背景深浅与层级都不一致。现全部统一为一个标准遮罩组件，背景统一为半透明黑、层级归入规范档位。**配色一律未动**（比如「整理历史名称」的紫色系完全保持原样），只有遮罩和层级被对齐。
- 优化（10 类过长提示改为弹窗）：手机提示条是**单行不换行**的黑色小条（375px 屏上约能放下 22 个汉字），超过就会被左右裁掉、根本读不全。排查发现 11 条提示已经溢出，其中最长的「已新增地点」有 746px、超出屏幕两倍多。现在这些「字多 / 需要你理解 / 涉及跨页操作」的提示改为弹出说明卡片，可以把要点一条条列清楚；纯成功类的短提示仍保持原来的轻量提示条。
- 修（按地点批量操作漏掉分区商品 · 重要）：商品的储存位置存的是**单值**——有分区的地点（如「冰箱」下的「冷藏 / 冷冻」）商品存的是**分区名**，只有不分区的地点才存地点名。此前「重命名地点」只对照地点名匹配，于是「冰箱」下的分区商品全被漏掉；虽然显示层能借分区名反查出地点、把名字跟上，可一旦那个分区被移除过就再也兜不住，位置标签会残留旧地点名。现已与「删除地点」的判定口径对齐。**注意两者处理方式不同**：删除地点时命中的商品（含分区商品）一律清空为「待设置」；重命名时只改「存了地点名」的那批，分区商品的位置值**保持不动**（分区名没有变，强行改写反而会把分区信息抹掉）。
- 修（状态切换瞬间出现不存在的配色）：顶栏同步指示灯切换状态时，底色和文字色各自做了 250 毫秒的渐变，两者时序错位，中间帧会出现「紫底配红字」这种本不该存在的组合。现改为状态色瞬时切换（只保留缩放过渡），并顺手修掉了同步中把指示灯压暗一半、与「正在同步」语义相冲的问题。
- 云同步入口说明：设置页「云端数据同步」板块的入口未变，本次只是在录入 / 批量页的顶栏多放了一个同款按钮。
- 使用指南（正文补充）：指南的「扫码录入」与「设置」两个模块的详细说明里补了三条——录入页顶栏也有云同步按钮、自动同步与顶栏状态指示灯的含义、以及删除 / 重命名位置时商品会怎样（删除→位置清空为「待设置」可再筛回；重命名→商品跟着改名、原有分区保持不变）。
- 使用指南（5 张手机示意图对齐真实界面）：示意图是手绘复刻真实页面的，几处改版没跟上，现逐张校正——①**所有示意图的页头**由「页面标题」改为真实的「应用图标 + FoodIn 词标 + 当前页名小字」两行结构（首页 / 扫码录入 / 操作记录 / 数据统计 / 设置）；②**记录页**顶部第一张筛选卡由「在库 5 件」改为「全部 7 条」——前者是商品维度、后者才是记录维度，且四张卡的配色改为各类型自己的语义色（蓝 / 橙 / 绿 / 红）而不是统一深灰；③**设置页**底部原本平铺着「云端数据同步 / 文字识别（小票 OCR） / 识别引擎」三张配置卡，实际这些早已收进「高级设置」二级页，故改为一张「高级设置」入口卡（副标题动态汇总已开启项）；④扫码页示意图的页头补上云同步按钮，与本次新增的入口一致。

## v2.34.0–2.34.3  <sub>2026-09-18</sub>

- 新增（百度云文字识别引擎）：原来的识别引擎只有 Paddle（本机跑，不上传图片）和 Tesseract（本机跑，兼容性最好但准确率一般）两种，都在设备本地计算。Paddle 走的是 WebGL 推理，**在苹果设备（iPhone / iPad）上必然初始化失败**——旧版会让你白等半分钟才悄悄换成 Tesseract。现新增第三个引擎「百度云」，把图片发到百度做识别，中文准确率明显更高（小票场景约 90%+），是专门为苹果设备准备的高精度通道。为了保护你的密钥，识别请求不直连百度，而是先发到你自建的一个中转服务（地址填在「设置 → 高级设置 → 文字识别」里），密钥只留在服务端、不进网页，因此不会被任何人从前端看到。点「保存设置」时会自动探一次中转服务是否可达，地址写错 / 服务没起 / 没配密钥都会在这时就明确告诉你，不会等到真正识别时才失败。引擎切换：识别引擎一栏现在有三个选项（Paddle 本地 / 百度云 / Tesseract），选哪个用哪个；若设备跑不了 Paddle，它会自动改用 Tesseract 并明确提示一次，不再静默降级。
- 新增（高级设置独立成页）：原来「云同步 / 条码查询 / 名称清洗 / 文字识别」四张配置卡都摊在设置主页上，找一项要划很久。现收进独立的「高级设置」二级页，设置主页只留一个入口；四张卡在新页面里直接平铺展开，点进去就能改，不用再层层点开。
- 新增（记录页类型筛选改为多选）：记录页顶栏的四张卡（全部 / 入库 / 消耗 / 浪费）原来是单选的，点「消耗」就没法同时看「浪费」。现改为**可多选**：点一张卡加上它，再点一张继续叠加，再点一下取消。选中态用该类型自己的语义色（入库橙 / 消耗绿 / 浪费红），不再一律深灰，看颜色就知道在看哪几类。
- 优化（顶栏四张卡的统计口径统一）：四张卡的数字原来各写各的，改一处容易漏另一处，出现「卡片数字」与「列表实际条数」对不上的情况。现改为由一张统一的数据表驱动，卡片与列表共用同一套口径——「件」= 当前列表里入库 / 消耗 / 浪费三类记录的数量合计。
- 修（填了生产日期 + 到期日期后，保质期单位按钮选错 · 重要）：录入时若先填生产日期、再填到期日期，系统会反算保质期。旧实现**无条件按「天」计算并强行把单位切成「日」**，于是「今天生产、明天到期」这种一天之差也能算对，但「1 月 1 日生产、7 月 1 日到期」会得到「181 天」而不是更好读的「6 个月」。现改为**自动挑最自然的单位**：谁最能整除、且来回换算不丢精度就用谁——1 天就是「1 日」，半年就是「6 个月」，跨年就是「1 年」。同时录入页、批量录入、商品编辑弹窗三处口径完全一致。
- 修（商品改不动 / 删不掉 · 重要）：云同步按商品 id 做增量收敛，多设备同时新增偶尔会让两台设备各自生成同一个 id，导致库里出现**两条 id 相同的商品**。此后按 id 查找只会命中第一条，于是「改名 / 改数量 / 删除」全都作用在了错误的那条上——表现就是点保存没反应、点删除删不掉。现在启动时会自动检测重复 id 并给后来那条重新分配新 id（控制台会记录一行日志），并**把这些商品名下的流水一并迁移到新 id**——旧实现只改了商品 id、没管流水，结果流水全部变成找不到商品的孤儿或错挂到兄弟名下。
- 修（同 id 商品共存时删商品会连带删掉别人的流水）：删除商品时流水是按 id 清的，而旧实现是「把这个 id 的所有流水全删掉」。当库里存在同 id 的两条商品时（见上一条），删掉其中一条会把另一条的流水也一起清空。现改为按**归属**判断：该 id 若已没有商品在用，就确认这些流水属于它、正常删除；若还有兄弟商品，则只删商品名能对上的那些，其余保留。
- 修（撤销「调整」后重建的商品字段类型不一致）：撤销一条调整记录、商品被重新放回库存时，储存位置与分类旧实现写的是空数组，而其他所有创建路径存的都是文本。虽然显示层能容错，但会让「这个字段是不是空的」这类判断失配。现统一为文本，与全局一致。

## v2.33.0  <sub>2026-09-15</sub>

- 优化（首屏加载提速 64%）：扫码用的 html5-qrcode 库有 375KB，却一直放在页面头部当同步脚本——浏览器必须把它下载、解析、执行完才肯开始渲染首屏，而它实际上只有你点开「扫条码」时才用得上。现改为**打开扫码时才按需加载**，并在首屏画完之后趁浏览器空闲提前把它偷偷下载好，所以你点开扫码时通常已经就绪、感觉不到差别。同时删掉了一份早就多余、代码里另有按需加载的二维码生成库（20KB）。首屏需下载的资源从 **604KB 降到 217KB**。
- 新增（手机版顶栏显示应用名）：手机版顶部原来只有当前页面的名字（首页 / 录入 / 记录…），看不出这是什么应用。现改为左侧常驻「图标 + FoodIn」，当前页名降为它下方的一行灰色小字。桌面版左侧栏本来就有同款品牌，故桌面版顶栏保持原样（仍只显示页名），不会出现两个品牌。
- 修（导览示例数据会被同步到云端，且残留无法清除 · 重要）：新手导览为了让你「有东西可点」，会往库里放 5 件演示商品（土鸡蛋、全脂牛奶…）和 7 条流水，并在导览结束时收回。但原实现把这些演示数据一起纳入了云同步的差额计算：导览途中你一旦真的操作了一下（比如按提示点「−1」），演示数据就会在 15 秒后**被推到云端**；如果你中途直接关掉页面，endTour 没机会跑，演示数据就留在了云上——而下次启动时本地的清理发生在同步引擎初始化**之前**，云端那几条永远等不到删除指令，于是「云端有、本地删」反复拉扯，家人的手机还会突然多出土鸡蛋、全脂牛奶这些根本不存在的商品。现在把演示数据从同步引擎里**彻底排除**：既不推它、也不为它生成任何事件，它只是导览期间的本机临时数据。
- 优化（新手导览启动时机）：原来写死「等 700 毫秒再亮起聚光灯」，这是个经验值——快机上白等 0.7 秒，慢机上 700 毫秒可能还没排完布局和字体，聚光灯量出的高亮框会偏（而且之后不会重测）。现改为等「字体度量就绪 → 两帧渲染完成 → 一小段稳定期」，位置一定量得准，典型设备上也能更早进入导览。
- 修（离线缓存的两个隐患 · Service Worker）：① 预缓存原本是「要么全成功、要么全失败」，只要有一个图标漏传或没部署，**整批预缓存全部作废**（应用退化为完全无缓存），而且失败被静默吞掉、控制台毫无线索；现改为逐个文件独立处理，个别失败不影响其余，失败项会明确打日志。② 资源加载失败时的兜底原本会返回**首页 HTML**——如果是 JS 文件拿到一份 HTML，浏览器会报「Unexpected token '<'」这种看着像代码语法错误、实际是缓存喂错内容的疑难问题；现改为明确返回 504，让浏览器按「资源加载失败」正常处理。同时把两个扫码库移出预缓存（它们已改为按需加载），避免安装时白下 395KB 跟首屏抢带宽。
- 改（提示文案统一到规范句式）：把 63 处直接拼接的提示话术统一收敛到项目既有的 5 个构造函数（成功 / 失败 / 引导 / 失败含原因 / 重复校验），句式与措辞风格一致，例如「云同步失败：HTTP 500」「请稍候，正在识别…」「「剩菜剩饭」无法删除，请改用其他分类」。全部为文案层面调整，不改变任何功能行为。

## v2.32.0  <sub>2026-09-15</sub>

- 修（撤销「调整」只回退本条记录改动过的字段）：旧版撤销调整是「拿操作前快照整体覆盖商品」，会把别的流水造成的字段变化一起吞掉——例如一条只改过「分类」的记录，预览里却列出「数量：1 → 2」并把数量也改回去（那个数量是后来入库带来的）。现改为：产生调整记录时同步记下**这条记录实际改动过哪些字段**（分类 / 价格 / 保质期…），撤销时只回退这些字段，其余一概不动。「名称清洗」这类内部调整只记「名称」一个字段。
