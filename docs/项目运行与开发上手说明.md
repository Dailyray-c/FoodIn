**FoodIn** —— 家庭食品库存与临期管理 PWA。扫码录入、地点/分区两级存放、临期提醒、吃/浪费/加热流水与撤销、统计看板、jsonbin.io 事件溯源云同步、离线可用、可安装到主屏。

1. **调 node 一律用 PowerShell**（bash 里跑 node 会以退出码 23 结束且**无输出**），路径写 `C:/…` 盘符形式（MSYS 会把 `/c/…` 解析成 `C:\c\…`）。

3. **bash 报 `ls: command not found`** → 先补 PATH：
   ```bash

   ```
4. **`http.server` 是单线程**：`_paddle_models` 缺失会让它卡住 → E2E 里 `page.route('**/_paddle_models/**', abort)`。

## 5. 构建

**唯一构建动作 = 重编译 Tailwind。**

```bash
./node_modules/.bin/tailwindcss -i ./src/tailwind.css -o ./styles.css --minify
# 等价：npm run build:css
```

**必须重编译的时机**：新增了**从未出现过**的 utility class（`lg:mt-auto`、`gap-2.5`、`grid-cols-6` …）。
**不需要重编译**：改内联 `<style>` 里的组件类（`.fi-*`）、改 JS 逻辑、改模板条件（用的类都已存在时）。

❌ 漏编译的症状极具欺骗性：**功能一切正常，只是样式不生效 / 高度塌陷为 0（用户点不到按钮）**。
判定某类是否已进 CSS：
```bash
grep -o 'lg\\:mt-auto' styles.css | head -1        # ✅ 用 -o，能找到就说明有
grep -c 'lg\\:mt-auto' styles.css                  # ❌ 永远返回 1（minified 只有一行），会误判
```
任意值类在 CSS 里是**转义形式**（`text-[11px]` → `.text-\[11px\]`）。

> ⚠️ 只要改动了 `index.html` / `styles.css` / `service-worker.js` / `vendor/` 中任一项，**都必须 bump SW `CACHE_NAME`**（用户端缓存的是旧 `index.html`）。

## 7. 开发规范（动手前请过一遍）

### 7.1 版本号与发版联动

- 格式 **`X.Y.Z`** 三位必填（`2.33` 不合法）。`X` 仅破坏性变更；`Y` 每次可发布功能/重要优化；`Z` 仅 Bug 修复与小调整（**纯修 Bug 绝不 bump Y**）。
- **版本四处联动，一个都不能少**：
  1. `index.html` 的 `CURRENT_VERSION`
  2. `service-worker.js` 的 `CACHE_NAME`（数值 **+1**，与 X.Y.Z 独立计数，但每次发版都要 +1）
  3. `index.html` 内的 changelog 条目
  4. **bump 前先备份三件套**：
     ```bash
     mkdir -p versions/vX.Y.Z && cp index.html service-worker.js styles.css versions/vX.Y.Z/
     ```
     `versions/` **永不删**；回退用 `cp versions/vX.Y.Z/* .`。

### 7.2 目录与命名约定

- 调试脚本 / 截图 / 日志**一律 `_` 开头**（`.gitignore` 已屏蔽 `_*.js` `_*.py` `_*.png` `_*.txt` `_*.log` `_*.json` `_*.html` `_*/`）。
- 非调试的参考文件（审计报告、设计 demo、说明文档）统一收进 `docs/`。
- 清理 = **移到 `%LOCALAPPDATA%/Temp/FoodIn-cleanup-<日期>/` 再确认，不直接删**。
- `versions/` 与 `backups/` 都不要手动动。

### 7.3 单文件开发的四条高频铁律

1. **❗同文件多 Edit 必须串行** —— 同一条消息里并发多个 `Edit` 只有 1 个生效，其余静默丢失。**一个 Edit 一条消息**。
2. **❗新增函数/状态必须同时进两个白名单**：`return{}`（模板能用）与 `window.__foodin`（E2E 能测）。漏第一个 = 不落盘；漏第二个 = 测不到。
3. **❗模板里 `@change` 一律显式传参**（`@change="fn(scanForm)"`）—— 无参写法会把 DOM Event 当第一个实参，带默认值的形参静默失效，且**只在某一种操作顺序下必挂**。
4. **❗改 UI 三件套**：新增 utility class → 重编译 Tailwind；utility 收敛成组件类 → **补 fontScale 三档等值规则**；弹层只用 `z-40` / `z-50` 两档（导览子系统例外）。

### 7.4 UI 规范要点（细则看 `UI规范.md`，这里只给最容易返工的）

- **提示二选一**：toast 是 `nowrap` + 无 max-width 的单行黑条（375px 下可用 ≈22 汉字）。**> 22 汉字**或属「失败 / 引导 / 长说明」→ 用说明弹窗 `showTip({title, body, points, tone, primary, action})`；**成功类**留 toast。
- **toast 只用 5 个构造函数**：`toastDone / toastFail(三参) / toastGuide(自带「请」) / toastErr / toastDup`。
- **弹层**：居中弹窗一律 `<div class="fi-modal" @click.self="…">`，别手写 `fixed inset-0 z-50 bg-black …`；底部抽屉型不套 `.fi-modal`。
- **商品 `location` 是单值**：有分区的地点存**分区名**，无分区才存地点名 → 按地点批量操作必须 `loc === pl.name || zones.includes(loc)`。删地点（全部清空）与改地点（只改写存地点名的那批）**处理口径不同，不能照抄**。
- **状态色瞬时切换**：状态切换不要走 `transition-all`，否则底色与字色各自渐变、时序错位（曾出现「紫底红字」）。截图验收要加**稳态复采样**。

### 7.5 Git 安全铁律（2026-09-07 事故后确立）

- ❌ **绝不 `git stash` + `git rebase` 组合**（曾被 SIGTERM 打断导致 `.git` 损坏、只能删库重建）。
- ❌ **禁 `git add .` / `git add -A`**（工作区有上百个 `_` 调试产物）。
- ✅ 安全流程：`git fetch origin master` → `git reset --mixed <FETCH_HEAD 的 OID>`（不碰工作树）→ `git add <明确文件>` → `commit` → `push`。
- ✅ `.git` 损坏修复见 `docs/FoodIn开发经验总览.md` §11（工作树文件不会丢）。
- ⚠️ `backups/` 由 CI 提交，本地常落后 → 用 `git checkout -- backups/` 追平，**切勿把本地旧版 commit 上去**。

## 8. 发布与部署

### 8.1 三个发布脚本怎么选

| 脚本 | 提交范围 | 何时用 |
|---|---|---|
| **`push-safe.sh`** | 白名单：`index.html` `service-worker.js` `styles.css` `UI规范.md` `push-safe.sh` `README.md` `.gitignore` `scripts/daily_expiry_check.py` **+ `versions/` 全量** | **常规发版**（默认用这个） |
| `push-clean.sh` | `git add -u`（已跟踪文件的改动/删除）+ `docs/` + `versions/` + `push-readme.sh`，并自带**敏感信息护栏** | 工作区清理整理后、或**新增 `docs/` 文档**后 |
| `push-readme.sh` | 只 `README.md` | 只想补推 README |

⚠️ **注意**：`docs/` 下的**新增**文件不在 `push-safe.sh` 白名单里 —— 新增文档（含本文）要走 `push-clean.sh` 或手动 `git add docs/`。
三个脚本都内置：直连 GitHub（强制清代理）、`FETCH_HEAD` OID 判活、非快进时「重新对齐 → 重演提交 → 再推」、**绝不用 rebase**。

```bash
./push-safe.sh "release(v2.34.14): 一句话说明本次改动"
AUTO_YES=1 ./push-safe.sh "…"     # 非交互
```

### 8.2 部署链路

```
push origin master
   └→ .github/workflows/deploy.yml（cp 白名单 → _site/ → upload-pages-artifact → deploy-pages）
        └→ GitHub Pages 生效（约 1 分钟）：https://dailyray-c.github.io/FoodIn/
```

- CI 白名单只拷贝：`index.html` `styles.css` `service-worker.js` `manifest.json` `icon-180/192/512.png` + `vendor/`。
  **新增顶层目录必须同步加 `cp -r <dir> _site/`**，否则线上 404。
- 三方一致性要求：**deploy.yml 拷贝清单 ⊇ `PRECACHE_ASSETS` ⊇ 页面里的 `src="./…"`**。
- 改过 SW 后，**线上需刷新两次**才能拿到新资源。
- 线上版本号可在 App「我的 / 设置」页查看；SW 版本可在 DevTools → Application → Service Workers 查看。
- Actions 偶发丢 webhook → 到 Actions 页手动 **Run workflow** 兜底。
